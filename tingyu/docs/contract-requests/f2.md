# F2（移动端 App）契约问题 / 建议

都不阻塞，前端已在 `areas/mobile` 内做了兼容处理。

1. **缺少 `GET /conversations/:id`**：聊天页要显示咨询师姓名/头像，目前先拉 `GET /conversations` 再按 id 查找。建议加单个会话接口（或在 `GET /conversations/:id/messages` 的响应里带上 conversation）。
2. **缺少 `GET /assessments/results/:id`**：结果页（刷新或从记录进入时）只能拉 `GET /assessments/results` 全量再查找。建议加单条接口。
3. **`Notification.link` 的约定**：种子里是 `/m/orders/:id`、`/m/messages/:id`（移动端路径），但网站（F1）也会展示同一条通知。建议约定 link 用中立路径（如 `/orders/:id`），由各端自行映射；移动端已经兼容 `/m/...`、`appointments|orders/:id`、`messages|conversations/:id`、`intake/:id`、`counselors/:id` 这几种写法。
4. **新人券状态**：`POST /coupons/claim {code:'NEW100'}` 重复领取时希望固定返回 409 `conflict`（前端据此提示「已领取过」）；另外建议 `UserCoupon` 增加 `code` 字段，前端现在只能靠 `amount === 100` 或标题含「新人」来判断是否已领新人券。
5. **`SessionRoom` 演示**：咨询室页面在 `canJoin=false` 时按 `joinOpensAt` 倒计时，到点后重新请求 `/room`。如果后端能提供一个「演示用：立刻可进入」的预约（种子里一条 10 分钟内开始的已支付订单），演示咨询室会更方便。
