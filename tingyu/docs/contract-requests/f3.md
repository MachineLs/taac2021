# F3（咨询师工作台）契约问题 / 需求

前端已做兼容处理，下面这些不阻塞，按优先级列出。

## 1. 来访列表需要达人名称（中）
`GET /workbench/appointments` 返回的 `Appointment` 只有 `creatorId`，来访列表「来源达人」一列拿不到名字，目前显示「达人推广 / 自然流量」。
名字只能逐条调 `wbBrief` 拿 `source.creatorName`，列表页不现实。
建议：`Appointment` 增加可选字段 `creatorName?: string | null`（或在 workbench 接口里附带）。

## 2. 咨询师无法主动发起会话（中）
`POST /conversations` 只接受 `{ counselorId }`，是来访者视角。简报页的「给来访者发消息」只能在已有会话里找（`GET /conversations` 按 `client.id` 匹配），
找不到时提示「该来访者还没有发起过留言」。
建议：counselor 角色调用时支持 `{ clientId }`（或 `{ appointmentId }`），仅允许与自己有预约关系的来访者。

## 3. 「待写记录」需要逐条拉简报（低）
今日页的待办「待写记录的已完成咨询」目前对最近 14 天内的已完成咨询（最多 5 条）逐个调 `GET /workbench/appointments/:id/brief` 判断有没有本次笔记。
建议：workbench 的 `Appointment` 附带 `hasNote: boolean`，或提供 `GET /workbench/todos`。

## 4. 笔记接口语义与文档不一致（文档）
`POST /workbench/appointments/:id/notes` 实际是「每个预约一条，存在则更新」（upsert），`ClientBrief.notes` 返回的是该来访者所有预约的笔记。
API.md 只写了「新增」。前端已按 upsert 实现（本次记录可编辑 + 往次记录列表），建议文档写明。

## 5. 被驳回后无法重新申请（低）
`POST /counselor-applications` 只要用户已有 counselors 行就 409，status=rejected 的申请人无法重新提交。
前端在 rejected 状态下会展示表单并提示「可完善资料后重新提交」，提交会得到 409（前端提示「你已提交过入驻申请」）。
建议：rejected 时允许覆盖更新并重置为 pending。另外可考虑在 `User` 上带 `counselorStatus`，免得前端再请求 `/counselors/:id`（目前依赖该接口对本人放行 pending 资料，已验证可用）。

## 6. 来访列表不含已取消（说明）
`GET /workbench/appointments` 排除了 `pending_payment` 和 `cancelled`。来访列表的「已取消」筛选因此恒为 0，如需展示请放开 `cancelled`。
