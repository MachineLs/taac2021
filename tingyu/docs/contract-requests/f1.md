# F1（网站 · 桌面端）契约问题与建议

前端已在 `apps/web/src/areas/site/**` 内做了兼容处理，以下为建议，不阻塞。

1. **通知 `Notification.link` 指向移动端路径**（例如 seed 里的 `/m/orders/<id>`）。
   网站端目前用 `areas/site/util.ts` 的 `siteLink()` 映射（`/m/orders/*` → `/account`，`/m/messages*` → `/account/messages` 等）。
   建议：link 存与端无关的语义路径（如 `/orders/<id>`），或增加 `target: { kind: 'appointment' | 'conversation' | …, id }` 字段，让各端自行路由。

2. **心理测评结果缺少危机标记**。PHQ-9 第 9 题（自伤念头）计分 > 0 时，`interpretation` 文案里写了热线，但前端无法结构化判断是否展示 `CrisisBanner`。
   建议：`AssessmentResult` 增加 `crisis: boolean`（或 `risk: RiskLevel`），与 intake 的 `crisis` 保持一致。

3. **筛选项没有数据来源**：找咨询师页的「城市」列表目前是前端静态常量（北京/上海/杭州/深圳/广州/南京/成都），首页「按困扰分类」的人数是对每个标签各请求一次 `GET /counselors?tag=&pageSize=1` 取 total（8 个请求）。
   建议：增加 `GET /counselors/facets` → `{ tags: {tag, count}[]; cities: {city, count}[]; priceRange: {min, max} }`。

4. **`GET /intake/sessions?mine=1` 的 summary**：详情页「把接待小结同步给咨询师」需要展示最近一次已结束接待的 `summary.mood`，当前实现会返回 summary（可用）。请在 API.md 中明确该列表**包含 summary**（目前只写了"不含 messages 也可"）。
