# F4（运营后台 + 达人后台）契约请求

前端已经按现有契约做了兼容处理，下面这些都**不阻塞**；补上后体验会更完整。

## 1. `Appointment` 缺少来源达人名称（订单列表「来源达人」列）
- 现状：只有 `creatorId`。前端额外调用 `GET /admin/creators`，按 id 映射出名称；映射失败时显示「达人推荐」。
- 建议：`Appointment` 增加 `creatorName: string | null`（或 `creator: { id; name } | null`）。

## 2. 咨询师审核缺少申请元信息（`GET /admin/counselors`）
- 审核需要：申请人手机号（电话核实资质）、提交时间、驳回原因（「已驳回」tab 要展示）。
- 建议：管理端返回 `CounselorDetail & { applicant: { userId; phone } ; appliedAt: string; reviewNote: string | null; reviewedAt: string | null }`。
- 另：各状态数量（tab 上的角标）目前只能在切到该 tab 后显示；可选地增加 `GET /admin/counselors/counts` → `{ pending; approved; rejected }`。

## 3. 危机预警缺少处置记录（SOP 第 3 步「记录处置过程」）
- 现状：`UpdateCrisisReq` 只有 `status`，`CrisisAlert` 没有处置备注与时间，SOP 要求的「记录」无处可存。
- 建议：
  - `UpdateCrisisReq` 增加 `note?: string`；
  - `CrisisAlert` 增加 `handledAt: string | null`、`resolvedAt: string | null`、`notes: { by: string; content: string; at: string }[]`。
- 前端目前在「标记已解决」前做二次确认（“已确认用户安全并记录处置过程？”），补上字段后会改为必填处置记录。

## 4. 达人佣金明细缺少订单实付金额
- `CreatorStats.commissions[]` 只有佣金 `amount`；明细里同时展示「订单实付 / 佣金」更清楚。
- 建议：增加 `orderAmount: number`。

## 观察（非契约问题，供 B2 参考）
- 种子数据下 `AdminOverview.daily[].intakes` 与 `appointments` 每天完全相等，两条折线重叠（图表与 tooltip 正常，只是看起来像一条线）。
- 种子数据中达人 `daily.signups / orders` 呈 0/1 交替，曲线呈锯齿；属于数据形态，不影响功能。

## 5. `CrisisAlert.handledBy` 语义不明确
- 现状：后端返回的是用户 id（如 `u_m2bysd2gikev`），前端需要展示「处理人」姓名。
- 建议：改为 `handledBy: { id: string; name: string } | null`，或明确为显示名。前端目前：等于当前用户 id 时显示「姓名（我）」，否则显示「运营账号 <id>」。
