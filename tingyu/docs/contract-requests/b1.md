# B1 契约问题 / 实现约定

## 需要负责人决定
1. **退款没有事件**：已支付订单退款（→ refunded）后，B2 在 `appointment.paid` 时计提的达人佣金不会被撤销。建议在 `core/events.ts` 增加 `appointment.refunded: { appointmentId }`，B1 退款时 emit，B2 据此作废 pending 佣金。批准之前 B1 不 emit（类型里没有这个事件）。
2. **发送验证码限流的状态码**：按任务要求返回 `409 { code: 'too_many' }`，但 API.md 的错误 code 列表里没有 `too_many`。建议加进列表（或者改成 429）。
3. **CounselorEarnings.platformFee 的注释**写的是「30%，达人首单为 20% + 达人 10%」，任务说明是固定 30%。目前按**固定 30%** 实现。如果要按注释算，请确认规则。
4. **`in_session` 状态**：没有接口会把订单置为 `in_session`（进咨询室只是 GET）。`complete` 和 `room` 都接受 paid/in_session。如果需要「开始咨询」的状态，需要新增接口。
5. **查看自己的入驻申请**：没有单独接口。前端可以用 `/me` 的 `counselorId` 调 `GET /counselors/:id`：B1 让档案本人和 admin 能看到 pending/rejected 档案，其他人看到的是 404。

## 实现约定（前端请注意）
- 优惠券在**支付成功时**才变成 `used`。待支付订单占用的券在 `/coupons/mine` 里仍显示 `unused`，但不能再用在另一笔待支付订单上（409）。订单超时或取消、退款后券会退回（已过期的变成 `expired`）。
- `POST /appointments`、`POST /coupons/claim`、`POST /workbench/slots`、`POST /counselor-applications`、`POST /appointments/:id/review` 返回 **201**，其他接口返回 200。
- `GET /appointments?status=` 支持用逗号传多个状态，比如 `paid,completed`。
- `GET /workbench/appointments` 不返回 `pending_payment`、`cancelled`（未支付的占位不进日程），返回 `refunded`。
- 工作台笔记：每个预约一条，再次 POST 就是更新内容（`updatedAt` 会变）。简报里的 `notes` 是该咨询师写过的、这位来访者所有预约的笔记（新的在前）。
- 简报 `source`：优先取订单上的 `creatorId`，没有的话取来访者注册时的归因达人。
- 评分用累计平均：`new = (rating × reviewCount + r) / (reviewCount + 1)`，所以种子数据的评分不会被冲掉。
- 排班新增：同一开始时间重复、或和已有时段重叠的会被忽略。之前被 blocked 的同一时间会重新开放。删除时如果有历史订单引用这个时段，就改成 blocked。
- 通知链接：来访者用 `/m/orders/:id`，咨询师用 `/desk/appointments/:id` 或 `/desk`。
- 管理员订单列表支持 `pageSize` 参数，默认 20，最大 100。
