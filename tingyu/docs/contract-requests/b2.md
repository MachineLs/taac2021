# B2 contract requests / notes

These are the parts of the contract B2 left unspecified and how B2 handled them. Nothing below blocks the frontend. B2 has already handled each one in its own modules.

## 1. IntakeSummary.scales: no way to mark a score as an estimate (suggestion)
The intake summary's PHQ-9/GAD-7/ISI scores are rough estimates from the conversation, not real test results. The current type has nowhere to say so.
- **What B2 does now:** `level` uses the same labels as real tests (for example `轻度`). The sentence 「量表分数为根据对话的初步估计，需正式测评确认。」 is added to the end of `riskNote`.
- **Suggestion:** add `estimated?: boolean` to `IntakeSummary.scales[i]`, or a top-level `scalesNote: string`. Then the frontend can tag these scores as 「初估」 itself.

## 2. Status codes and HTTP details (as implemented, for frontend reference)
- `POST /intake/sessions` returns **201**.
- `POST /assessments/:scale` returns **201**.
- `POST /mood` returns **201**.
- `POST /conversations/:id/messages` returns **201**.
- `POST /conversations` returns 200, whether the conversation is new or already existed.
- A session bound to a user:
  - No login → 401.
  - Someone else's session → 403. Admins can read it.
- `reply` to an ended session → 409 `conflict`. Calling `end` again on an ended session returns the existing summary (idempotent).
- `claim` on a session that belongs to another account → 403.
- `GET /mood?days=` accepts 1..365 and returns **newest first**. The order was not specified in the contract. Frontend charts should sort as needed.
- `GET /conversations/:id/messages` returns **oldest first**.
- `GET /notifications` returns newest first, at most 100.

## 3. Crisis alerts
- **Messages:** an alert is created only from the client's own messages (`source='message'`), because counselors may legitimately mention crisis words. `CrisisAlert.sessionId` is `null` for these, since it means an intake session id.
- **Intake:** at most one open or handling alert is kept per intake session. Later crisis messages in the same session still get the crisis reply and the `crisis` payload, but no new alert.
- **Admin notifications:** every new alert sends a `notify()` to all admins with type `crisis` and link `/admin/crisis`.
- **PHQ-9 item 9 positive:** writes an alert with `source='intake'`, `session_id=null` and `excerpt='PHQ-9 第 9 题阳性'`, following the lead's instruction.
- **Suggestion:** add a source `'assessment'`.

## 4. Order states counted as a "paid first order" / GMV
`paid`, `in_session` and `completed`. `in_session` is also a paid state, so it is included. `refunded` and `cancelled` are not counted.

## 5. `appointment.refunded`
On refund, a commission that is still `pending` is **deleted**. A commission that is already `settled` is kept and needs manual follow-up. The schema has no `void` status, so the commission cannot be marked void.
